# Zahlenraten — версія за твоїм Mockup

Python + Flask + SQLite. Інтерфейс німецькою відтворює п'ять станів наданого PDF: старт із Bestenliste, гра з історією, помилка введення, перемога з місцем у рейтингу та мобільна версія.

## Запуск у Windows / VS Code

Розпакуй ZIP повністю. Відкрий папку `zahlenraten`, у якій лежить `app.py`. У Terminal → New Terminal (PowerShell) виконай:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Відкрий http://127.0.0.1:5000. Зупинка сервера — Ctrl+C. Наступного разу потрібна лише остання команда. Python 3.13 підходить. Активувати `.venv` не потрібно, тому проблеми з PowerShell Execution Policy та Windows-аліасом `python` не заважають запуску.

Альтернатива для локальної розробки:

```powershell
.\.venv\Scripts\python.exe -m flask --app app run --debug
```

Це навчальний локальний застосунок; debug не призначений для публічного сервера.

## Що змінилося за макетом

- Світле тло, біла верхня панель, сині кнопки, дві колонки на комп'ютері.
- Стартова сторінка містить загальну Bestenliste, а не історію лише одного імені.
- Підказка показує введене число й напрямок: «42 ist zu klein. … rate höher.»
- «Deine Tipps» містить усі допустимі спроби в порядку введення.
- «Noch möglich» та смуга показують діапазон, який випливає з попередніх підказок.
- Недопустиме значення залишається в полі, помилка пояснює причину; лічильник і діапазон не змінюються.
- На сторінці перемоги є місце в рейтингу, позначка «Du» та «Dein Weg zur Zahl».
- «Nochmal spielen» запускає нову партію з тим самим ім'ям, інша кнопка повертає до введення імені.
- «Spiel beenden» перериває гру; незавершені партії не потрапляють до рейтингу.
- На телефоні контент розміщується однією колонкою, а історія показана компактними плашками.
- «Spielregeln» відкриває окрему сторінку правил; «Bestenliste» переводить фокус до таблиці.

Імена Tom, Aylin тощо у PDF — демонстраційні. У готовій програмі вони не створюються автоматично: чиста база спочатку має порожню Bestenliste. Число кожної нової гри випадкове, а не завжди 47.

## Як працює SQLite

При першому запуску автоматично створюються `instance/zahlenraten.db` і `instance/secret_key.txt`. База — локальний файл. MySQL, окремий сервер БД та SQLAlchemy не потрібні. Не публікуй secret_key.txt або власну базу з іменами гравців.

Таблиця `games`: один рядок — одна партія.

| Поле | Зміст |
|---|---|
| id | Випадковий ідентифікатор |
| player_name | Ім'я, 1–50 символів |
| secret_number | Загадане число від 0 до 100 |
| attempts | Кількість допустимих спроб |
| last_guess | Остання допустима спроба |
| won | 0 — без перемоги, 1 — перемога |
| started_at | Початок, UTC |
| ended_at | Час перемоги, UTC; спочатку NULL |

Таблиця `guesses`: один рядок — одна допустима спроба.

| Поле | Зміст |
|---|---|
| game_id | Посилання на games.id |
| sequence | Номер спроби в партії |
| number | Введене число |

Співвідношення: одна гра має багато спроб. Разом `(game_id, sequence)` утворюють первинний ключ — одна й та сама спроба не записується двічі. Лічильник і рядок історії оновлюються однією транзакцією.

`get_db()` відкриває з'єднання через `sqlite3.connect()`. `sqlite3.Row` дозволяє читати стовпці за назвою. `close_db()` закриває з'єднання після запиту. SQL використовує параметри `?`, а не вставляє користувацьке введення в текст запиту.

При старті зберігається рядок із нулем спроб. Кожна допустима спроба оновлює цей рядок і дописує `guesses`. При перемозі встановлюються `won = 1` і час завершення. Ім'я вже є в рядку від початку.

У cookie зберігається лише ідентифікатор гри та службові дані, а не загадане число. Повторне відкриття застосунку не видаляє результати.

## Рейтинг

- Показуються 10 найкращих завершених партій усіх гравців.
- Менша кількість спроб означає кращий результат.
- При однаковій кількості спроб місце спільне: наприклад 1, 1, 3.
- Серед рівних результатів раніше завершений показується першим; id вирішує повний збіг часу.
- На сторінці перемоги поточна партія додатково показується, навіть якщо вона поза першою десяткою.
- «Du» позначає конкретну поточну партію, а не всі записи з таким самим ім'ям.
- Кожна перемога — окремий запис. Ім'я є псевдонімом, а не обліковим записом.

## Діапазон можливих чисел

Спочатку це 0–100. Після «50 zu groß» верхня межа стає 49. Після «25 zu klein» нижня межа — 26. Після «42 zu klein» отримуємо 43–49.

Нижня межа — найбільша з підтверджених нижніх меж, верхня — найменша з верхніх. Повторний слабший Tipp не розширює діапазон. Дозволено вводити будь-яке ціле число 0–100, навіть якщо попередні підказки вже виключили його; така спроба рахується. Числа поза 0–100, дроби й текст не рахуються.

## Маршрути Flask

| Метод і адреса | Дія |
|---|---|
| GET / | Старт, введення імені, рейтинг |
| POST / | Створення нової партії |
| GET /game | Поточна гра |
| POST /game | Перевірка й запис спроби |
| GET /result | Результат і оновлений рейтинг |
| POST /end | Вихід із поточної гри |
| GET /rules | Правила |

Після POST виконується redirect на GET: звичайне оновлення сторінки не повторює спробу. Номер спроби у формі захищає від повторного надсилання застарілої форми. CSRF-токен перевіряє, що форма належить поточній сесії.

Вкладки одного браузера ділять session. Для двох незалежних гравців використовуй різні браузери або окремі приватні сеанси.

## Оновлення попередньої версії

Перед заміною зроби резервну копію своєї папки `instance`. Замінюй код і шаблони, залишаючи свою `instance` та `.venv`. Нова таблиця guesses створиться автоматично, старі результати збережуться.

Стара версія зберігала лише останню спробу. Для старих партій буде перенесено тільки її з правильним номером; відновити попередні введені числа неможливо. Нові партії мають повну історію.

## Нефункціональні Anforderungen

| ID | Реалізація / перевірка |
|---|---|
| NF1 | Семантичний HTML, видимі підписи, повідомлення словами й кольором, контраст, фокус; повна перевірка доступності ще потребує screenreader |
| NF2 | Одна основна форма на крок, короткі інструкції |
| NF3 | Візуальна ієрархія і дві колонки згідно з Mockup |
| NF4 | Tab/Shift+Tab/Enter; skip-link; усі дії — звичайні кнопки/посилання |
| NF5 | Кожне поле має label з for/id |
| NF6 | Помилки пояснюють діапазон та що спроба не рахується |
| NF7 | HTML/CSS, стандартні форми; логіка працює без JS |
| NF8 | Локальний файл SQLite з постійними даними |
| NF9 | Локальні CSS/JS без зовнішніх шрифтів; індекс БД, Top 10; масштабне навантаження не перевірене |
| NF10 | Німецькі тексти, правила й пояснення кожного кроку |

`lang="de"` задає мову. Помилки мають `role="alert"` та пов'язані з полем через `aria-describedby`; є `aria-invalid`. Підказка має `role="status"`. Після перезавантаження поле отримує фокус і пов'язане з текстом підказки, діапазоном і помилкою. Виграш переводить фокус на заголовок. Підказки зрозумілі без розрізнення кольорів, смуга доповнюється текстом.

Вимога NF1 не є автоматично сертифікованою відповідністю WCAG. Перед здачею перевір також NVDA або іншим screenreader, масштаб 200%, клавіатуру та потрібні браузери.

## Тести

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

11 тестів охоплюють: повну гру, некоректні значення, межі 0/100, повторне надсилання, незалежні браузери, постійність БД, імена зі спеціальними символами, захист форм, сценарій Mockup, ранжування/нічиї/переривання, міграцію старої бази та поточний результат за межами Top 10. Використовуються тимчасові бази, твої дані не змінюються.

## Перегляд бази через Python

Запусти `py` у папці проєкту:

```python
import sqlite3
connection = sqlite3.connect('instance/zahlenraten.db')
for row in connection.execute('SELECT player_name, attempts, won FROM games'):
    print(row)
connection.close()
```
